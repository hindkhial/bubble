# Private candidate manual verification

All results below start **Not Tested**. Automated assertions, exports and simulated viewport sizes do not establish human usability or physical-device passes. Keep PR #8 draft and all release gates open until evidence is recorded.

## Setup and evidence

1. Record candidate SHA, tester/date, operating system, browser, device, screen reader and versions. Use a dedicated test browser profile and synthetic accounts/content only. Never clear a personal profile or storage to prepare a test.
2. Establish approved, verified HTTPS using LOCAL-HTTPS.md. Stop on any certificate warning. The existing loopback-only Mac staging cannot be reached directly by a phone. Physical testing needs a separately approved private route, matching certificate hostname and test-device trust plan; do not change network bindings, install device roots or expose staging to make this checklist work.
3. Seed a note with a long title/body, a checklist with short/long items, pinned and unpinned content, and a long profile bio. Keep a second synthetic account with distinct content. Also test a fresh local-only profile with no content.
4. Repeat critical flows in local-only and account modes: Home → Add note → edit/save → Search/open → pin/unpin → Add checklist/complete item → You/edit profile → Appearance → refresh/reopen. Confirm data and preferences remain; log out and verify another account cannot see the first account's content. Local-only content must remain separate. Delete only your synthetic fixtures when finished.
5. For each row record Passed, Failed or Not Tested, expected/actual behavior and private evidence/issue reference. Failed TLS setup means dependent tests remain Not Tested, not Passed. Do not attach passwords, session cookies, traces or private data to public issues.

## What automation can establish

Codex can run TypeScript, frontend unit/persistence tests, Java/PostgreSQL tests, web/backend builds, nine sandboxed HTTPS browser scenarios, image scans, and synthetic migration/backup/restore/restart/compatible-rollback checks on disposable CI infrastructure. See TESTING.md for commands and exact run evidence. Those checks do not replace the matrix above. VoiceOver/TalkBack usability, full visual assessment and physical devices require a person with the actual tools; no such execution is claimed here.

## Result record template

Copy one record per test/route/variant: `ID; candidate SHA; tester/date; device/OS/browser/reader versions; viewport/zoom/font scale/theme; mode; steps executed; expected; actual; Passed|Failed|Not Tested; private evidence/issue; cleanup`. A failure needs a reproducible issue and retest at the fixing SHA. A missing prerequisite stays Not Tested. Security risk acceptance and release approval are separate decisions from completing this matrix.
